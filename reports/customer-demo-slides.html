实线：实际私网协议通信虚线：策略 / DNS 配置关系

官方配置顺序

  1. 检查前提和实际区域
    托管环境、角色和许可；Get-EnvironmentRegion 确认区域配对。
  2. 准备 Azure 网络
    注册 Network / PowerPlatform RP；建配对网络，委派专用子网。
  3. 创建 NetworkInjection 企业策略
    location 用 Power Platform geography；引用两区的 VNet / 子网。
  4. 确保关联者能读取策略
    不同关联人补策略范围 Azure Reader，并有 Power Platform 管理权限。
  5. 关联环境并确认完成
    Enable-SubnetInjection 或管理中心；确认 History 为 Succeeded。
  6. 另做真正的网络验收
    从环境内做 DNS / TCP / TLS 和公网拒绝对照，不只看“已关联”。

02 / ADDRESS PLANNING & BEST PRACTICES

网段规划：专用、对称、不重叠、留余量

示例地址是本 demo 的已部署配置；生产应服从企业 IPAM，而不是直接照抄示例 CIDR。

West US · 独立目标子网172.20.1.0/2727（32 − 5）非委派；Blob PE 172.20.1.4；端点 NSG 允许源 /24 的 TCP 443。

容量：按环境和峰值算，不按用户人数猜

  • 官方经验估算：生产 25–30 IP / 环境，非生产 6–10 IP / 环境；以实际负载和伸缩验证。
  • Azure 每个子网保留 5 个地址。配对委派子网应有相同可用地址数，并预留未来环境及峰值余量。
  • /24 是 demo 的宽裕容量选择，不是官方对所有客户的最小要求；端点子网大小也按端点数规划。
规划公式：每环境 IP 预算 × 环境数 + 5 个保留地址 + 伸缩余量。
示例：4 × 30 + 5 = 125，至少 /25；20 × 10 + 5 = 205，至少 /24（以上尚未额外留余量）。

隔离、解析与运维边界

  • 遵循企业 IPAM，避开本地、VPN、Hub/Spoke、容器地址；未来需要 peering 的 VNet 网段不得重叠。
  • 委派子网专用；同一子网不用于多个 Enterprise Policy。同一策略可关联多个环境，但必须合并容量预算。
  • 使用正常服务 FQDN，Private DNS 链接到需要解析的 VNet；NSG / 路由放行必要流量，生产公网依赖需受控出站设计。
  • 启用后不要直接改 CIDR 或 VNet DNS 地址；按官方停用 / 支持 / 重新启用流程评估变更与约 30 分钟影响窗口。
双区域 VNet 配对是平台配置要求，不等于业务故障切换已经验收。本 demo 仅在 West US 添加一个 PE 以控制成本；生产要分别验证两区 DNS、后端可达性与故障切换设计。

配置 / 维护过程的权限

任务最小授权思路 / 范围
建 VNet、子网、PE、DNS对应网络权限 / Network Contributor限制到目标 RG / VNet；创建 Storage 另需该资源写入权限。
创建企业策略RG Contributor 或精简自定义角色显式包含 Microsoft.PowerPlatform/enterprisePolicies 的 read / write；Network Contributor 不自动涵盖这些操作。
订阅准备、授予数据角色按任务交给对应管理员RP 注册 / 新建 RG 涉及订阅权限。授予 Azure RBAC 需 roleAssignments/write，例如适用范围的 Owner / User Access Administrator / RBAC Administrator。
托管环境、关联策略Power Platform Administrator + 策略可读按官方前提配置；不同关联人可补策略范围的 Azure Reader。本 demo 的 Global Administrator 为 PIM 临时激活，不是生产默认建议。

后续创建 / 使用工作负载的权限

层次授权与边界
应用 / 流程使用与制作共享访问 + 对应环境角色制作资源按需用 Environment Maker；普通使用者不需要 Azure Owner 或 Global Administrator。
Dataverse 表与数据实际数据安全角色按应用/表/行权限授权；System Administrator 仅给确需环境数据管理的人。Environment Maker 不自动授予数据权限。
私有后端访问给“连接的执行身份”授予数据权限只读用 Storage Blob Data Reader，读写按需用 Data Contributor，缩小到账户/容器。Azure 管理角色或 VNet 连通不替代数据授权。
托管环境产品许可适用 Premium / D365 权益或计费需符合应用、云流、代理的许可条款。Developer Plan 不替代 Managed Environment 中资产运行许可；本 demo 未运行业务资产。
本次会议诊断身份：脚本要求活跃的 Power Platform Administrator 或 Global Administrator，并能读取 Azure 网络/端点/存储配置；仅在新增存储上有 Blob Data Reader，用于带身份的公网拒绝对照。这是管理诊断权限，不应复制给所有终端用户。
环境 / Dataverse 角色范围 Blob 数据面 RBAC Managed Environment 许可 Azure 网络角色
结论：Azure Owner ≠ Power Platform 管理员；路径可达 ≠ 数据可读；管理员角色 ≠ Premium 许可证。最小权限 · PIM · 定期复核
