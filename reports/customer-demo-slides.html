实线：实际私网协议通信虚线：策略 / DNS 配置关系

官方配置顺序

  1. 检查前提和实际区域
    托管环境、角色和许可；Get-EnvironmentRegion 确认区域配对。
  2. 准备 Azure 网络
    注册 Network / PowerPlatform RP；建配对网络，委派专用子网。
  3. 创建 NetworkInjection 企业策略
    location 用 Power Platform geography；引用两区的 VNet / 子网。
  4. 确保关联者能读取策略
    不同关联人补策略范围 Azure Reader，并有 Power Platform 管理权限。
  5. 关联环境并确认完成
    Enable-SubnetInjection 或管理中心；确认 History 为 Succeeded。
  6. 另做真正的网络验收
    从环境内做 DNS / TCP / TLS 和公网拒绝对照，不只看“已关联”。

02 / ADDRESS PLANNING & BEST PRACTICES

网段规划：IP 用途与容量计算依据

委派 IP 分配给运行容器，而非每个用户、流程或请求；VNet 地址池、委派子网与端点子网分别估算。

3 / 5
参考部署地址范围IP 分配对象与用途容量规划依据
VNet 地址池
172.20.0.0/16 / 172.21.0.0/16		容纳各类子网和未来扩展；划出地址池不等于启动同等数量的实例。子网总需求 + 未来扩展；遵循 IPAM，不与本地、VPN、未来对等网络重叠。/16 不是固定要求。
两区专用委派子网
172.20.0.0/24 / 172.21.0.0/24		执行插件 / 受支持连接器请求的运行容器 NIC。每容器 1 IP，同一容器可处理多个并发请求。同一策略下各环境峰值需求之和 + 余量；两区均为 251 个可用 IP，不是合计后对半分。
独立非委派端点子网
172.20.1.0/27 · 27 个可用 IP		Private Endpoint NIC 的目标私网 IP；Blob PE 用 172.20.1.4，不是把整个 Storage 服务放进子网。各 PE 实际所需 IP 数 + 5 个保留地址 + 扩展余量；不占用 Power Platform 专用委派子网。

① 先估算每个环境的峰值容器需求

  • 按环境数汇总：同一策略 / 子网承载的全部环境纳入预算；用户数、流程数或业务数据量不能直接换算为 IP 数。
  • 官方经验起算：生产 25–30 IP / 环境，非生产 6–10 IP / 环境；是参考范围，不是硬上限或容量保证。
  • 根据峰值修正：调用并发和持续时间影响容器伸缩；结合高峰 / 压测及 Get-EnvironmentUsage 的实际占用，计入伸缩和增长空间。

② 加余量和保留地址，再选 CIDR

每个委派子网分别满足：
2^(32 − 前缀长度) − 5 ≥ Σ(各环境峰值 IP 预算) + 余量

示例：4 个生产环境 × 30 IP + 30 IP 余量 = 150 个可用 IP；加 5 个 Azure 保留地址，需要至少 155 个总地址。

/25：128 − 5 = 123，容量不足。
/24：256 − 5 = 251，可容纳 150。
30 IP 余量为示例参数，不是官方固定比例。

参考部署的 /24 与端点 /27 均包含容量余量，不是所有场景的最低网段。

配对委派子网可用 IP 数应相同；同一子网不用于多个企业策略。启用后不要直接改 CIDR / VNet DNS，应按官方变更流程评估停用、支持及重启窗口。两区后端可达性和灾备仍需独立验收。
关键区分：运行容器的源 IP ≠ 私有端点的目标 IP；容量按峰值运行实例规划，不按用户一一分配。官方 IP 用途与容量文档 →

配置 / 维护过程的权限

任务最小授权思路 / 范围
建 VNet、子网、PE、DNS对应网络权限 / Network Contributor限制到目标 RG / VNet；创建 Storage 另需该资源写入权限。
创建企业策略RG Contributor 或精简自定义角色显式包含 Microsoft.PowerPlatform/enterprisePolicies 的 read / write；Network Contributor 不自动涵盖这些操作。
订阅准备、授予数据角色按任务和资源范围授权RP 注册 / 新建 RG 涉及订阅权限。授予 Azure RBAC 需 roleAssignments/write，例如适用范围的 Owner / User Access Administrator / RBAC Administrator。
托管环境、关联策略Power Platform Administrator + 策略可读不同关联人可补策略范围的 Azure Reader。参考部署使用 PIM 临时激活 Global Administrator；生产优先采用较小的适用角色。

后续创建 / 使用工作负载的权限

层次授权与边界
应用 / 流程使用与制作共享访问 + 对应环境角色制作资源按需用 Environment Maker；普通使用者不需要 Azure Owner 或 Global Administrator。
Dataverse 表与数据实际数据安全角色按应用/表/行权限授权；System Administrator 限于确需数据管理的身份。Environment Maker 不自动授予数据权限。
私有后端访问连接执行身份的数据面授权只读用 Storage Blob Data Reader，读写按需用 Data Contributor，缩小到账户/容器。Azure 管理角色或 VNet 连通不替代数据授权。
托管环境产品许可适用 Premium / D365 权益或计费需符合应用、云流、代理的许可条款。Developer Plan 不替代 Managed Environment 中资产运行许可；参考验证未运行业务资产。
诊断脚本的执行权限：活跃的 Power Platform Administrator 或 Global Administrator，以及 Azure 网络/端点/存储配置读取权限；测试存储账户上的 Blob Data Reader 用于带身份的公网拒绝对照。管理诊断身份与普通工作负载使用身份应分离。
环境 / Dataverse 角色范围 Blob 数据面 RBAC Managed Environment 许可 Azure 网络角色
结论：Azure Owner ≠ Power Platform 管理员；路径可达 ≠ 数据可读；管理员角色 ≠ Premium 许可证。最小权限 · PIM · 定期复核
