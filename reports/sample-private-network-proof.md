# 实际私网协议证据的公开脱敏示例

本文记录参考部署的证据结构与验收条件。账户、租户、订阅、服务域名和请求标识均未公开。

> **历史证据示例，不代表当前环境的运行状态。**
> 本文仅保留参考部署的通用网段与证据结构，不向任何服务发起请求。
> 实际验收以部署环境内的新测试、运行时间戳和原始 JSON 为依据。

## 证据结构

| 检查项 | 脱敏示例 | 验收条件 |
| --- | --- | --- |
| 委派子网来源 | `172.20.0.4` / `172.20.0.5` | 实际 Power Platform 诊断来源必须位于环境的委派子网内 |
| 私有端点目标 | `172.20.1.4:443` | 私有 DNS 和直接 TCP 目标必须匹配 PE NIC 的真实 IP |
| TLS | 参考部署通过 TLS 1.3、微软 Blob 证书和 CRL 检查 | 使用正常服务域名验证握手与证书，记录撤销检查的实际状态 |
| 公网反向对照 | HTTP `403 AuthorizationFailure` | 同时核对后端公网关闭、有效身份和数据角色；不能只凭任意 403 下结论 |

## 验收链条

1. 在 Power Platform 环境内解析正常服务 FQDN，结果为私有端点 IP。
2. 由委派子网内的诊断容器直接连接该私有 IP 的 TCP 443。
3. 通过正常域名完成 TLS 握手，检查证书、协议、错误和 CRL 状态。
4. 确认目标 `Public Network Access=Disabled`，带有效授权身份的公网请求被拒绝。
5. 按运行时间戳保存原始证据，区分当前实测、历史记录和本文的公开示例。

## 适用边界

验证结果只涉及协议数据包往返，不等同于连接器或插件的业务对象读写、
区域灾备或产品许可验收。配置 `Succeeded`、使用量映射或本机 TLS 成功，
不能单独证明 Power Platform 的实际私网路径。

原始运行证据和本地生成报告不属于公开仓库；新测试结果由
`Test-PrivateNetworkPath.ps1` 写入本机 Markdown 和 JSON 文件。
